## 真实生成发现的问题与候选修正

2026-10-25，用户授权后以其指定图片执行了首次真实生成。15 秒视频成功生成、通过安全审核并保存到作品列表，账本只扣除一次 300 积分；但成片仍保留参考视频中的人物，主体替换验收失败。服务器收到的图片与用户文件逐字节一致，已排除选错图片和上传内容变化。

接口参数符合 fal 官方 schema。当前证据无法证明 `disabled` 或普通 `Image 1` / `Video 1` 引用语法是根因。候选修正明确要求从首次出镜起替换原片唯一人物，图片独占主体外观，视频只提供环境与动作；移除 `No identity swaps` 的歧义，并仅为 Window Peeper 启用 fal `quality` 提示词改写。Ozil 仍保持原设置，模型、时长、分辨率、300 积分及保存、安全审核、幂等处理不变。

官方依据：<https://fal.ai/models/minimax/hailuo-03/reference-to-video/api>。`quality` 是受支持的改写选项，不保证人物替换成功。第二次真实生成前，不将候选修正记为已解决。

## 改用原生 FFmpeg

用户明确要求网站在视频生成后调用 FFmpeg 添加固定配乐，再恢复审核并保存作品。Cloudflare Workers 复用现有 Fal 账号调用 `fal-ai/ffmpeg-api/merge-audio-video`，输入已生成视频、本站固定音轨和零偏移，不创建新生成任务。已移除旧 JS remux 实现及其专用限制。

- 原 `provider_id` 始终保留模型生成任务；同一任务的 `assets` 持久化 FFmpeg 源地址、队列句柄及最终输出地址。合成提交、轮询、下载与审核分别推进。
- 未知提交结果不盲目重发；状态读取、最终文件下载故障只重试已保存的子任务。明确失败或文件超限沿用一次退款规则。
- 合成输出原样下载到私有 R2，新审核键绑定具体候选 UUID，并兼容在途历史任务；最终 key 和 ETag 通过审核后才开放播放下载。
- 发布前已用无私人信息的 15 秒测试片执行真实 Fal FFmpeg 调用：输出保留 15 秒/60 帧，完整解码通过；固定配乐波形相关系数 0.999396、时间偏移 0，视频 SSIM 0.997712。该接口重新编码，不能宣称压缩包或像素完全不变。
- 真实任务恢复、最终版本和线上检查结果在发布完成后追加；恢复过程中不重新扣除用户生成积分。
